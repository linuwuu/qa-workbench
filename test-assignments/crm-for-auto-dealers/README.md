# Тестовое задание: форма регистрации и логина в CRM для автодилеров 

## Контекст

Доступа к спецификации и внутренней логике системы у меня нет, поэтому
точный механизм регистрации мне неизвестен. Чек-лист, тест-кейсы и
баг-репорты построены на допущениях, которые нужно сверить с реальными
требованиями.

## Допущения и несоответствия
- Ссылка из задания ведёт на форму входа, а не регистрации. 
- Форма регистрации по ссылке недоступна, открывается форма входа. Чтобы результаты можно было проверить на реальном сайте, тест-кейсы и API-пример выполнены по форме входа, так как она доступна, и нет слов-ограничителей которые запрещают это.
- Чек-лист составлен для регистрации на основе типичных полей и специфики CRM для дилеров.
- Баги, которые не воспроизведены на сайте, помечены как «гипотеза».
- API-пример составлен по наблюдениям во вкладке Network в Chrome DevTools на странице входа. Из DevTools взяты метод и путь запроса, его тип и статус ответа. Всё, чего в DevTools не видно (имена полей, заголовки, формат успешного ответа), помечено как допущение.
- Если нужны тест-кейсы и API-пример именно для регистрации, могу подготовить их на основе чек-листа.
