## BUG-REPORTS

### BUG-SEC-001. Ссылка-приглашение не гасится после использования: по одному токену можно создать неограниченное число аккаунтов
(гипотеза)

| Поле | Значение |
| --- | --- |
| Severity | Critical |
| Priority | P0 (блокер) |
| Компонент | API регистрации |
| Окружение | Stage, Chrome 156, Windows 11, Postman |
| Связано |  PC-01  |

Предусловия: админ дилера отправил приглашение на `anya-nyan@mail.ru` с ролью «Менеджер по продажам». Ссылка действующая, срок не истёк. Токен приглашения: `9f3c2a7e-41b8-4d6a-b0e2-7c5d1f8a9e34`.
Примереый шаблон запроса для шагов 3-5:

```
curl -i -X POST "https://stellantis.autocrm.ru/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -H "Origin: https://stellantis.autocrm.ru" \
  -H "Referer: https://stellantis.autocrm.ru/login" \
  --data-urlencode "_csrf={{csrf_token}}" \
  --data-urlencode "LoginForm[email]={{email}}" \
  --data-urlencode "LoginForm[password]={{password}}"
```


Шаги:

1. Зарегистрировать `anya-nyan@mail.ru` по ссылке-приглашению с валидными данными и подтвердить почту (как в PC-01). Аккаунт создан.
2. Открыть ту же ссылку-приглашение ещё раз.
3. Перехватить запрос `POST /api/v1/auth/register` (DevTools → Copy as cURL или Postman), заменить в теле `email` на `stranger@example.com`, остальные поля оставить валидными, токен не менять.
4. Отправить запрос, подтвердить почту и войти под `stranger@example.com`.
5. Повторить шаги 3–4 ещё раз с другим email.

Attachments: cURL первого и повторного запросов, скриншот ответа 201 на повторный запрос, скриншот списка сотрудников с тремя лишними пользователями.

Влияние: приглашение превращается в постоянный вход в CRM дилера. Любой, кто получил ссылку, может завести себе аккаунт и увидеть клиентов, сделки и персональные данные. Админ дилера теряет контроль над тем, кто есть в системе.





### BUG-DUP-002. Email в другом регистре создаёт второй аккаунт того же сотрудника
(гипотеза)

| Поле | Значение |
| --- | --- |
| Severity | Major |
| Priority | P1 |
| Компонент | Форма и API регистрации |
| Окружение | Stage, Chrome 156, Windows 11 |
| Связано | NC-01 |

Предусловия: в системе есть аккаунт `top-dealer@mail.ru`. Есть новая ссылка-приглашение.

Шаги:

1. Открыть ссылку-приглашение.
2. В поле Email ввести `top-Dealer@Mail.ru`, остальные поля заполнить валидно.
3. Нажать «Зарегистрироваться».

Фактический результат: создан второй аккаунт. В списке сотрудников два «топ-диллера», вход по `top-dealer@mail.ru` открывает старый аккаунт.

Ожидаемый результат: email сравнивается без учёта регистра. Показана ошибка «Пользователь с таким email уже зарегистрирован», второй аккаунт не создан.

Влияние: сделки и клиенты расходятся по двум аккаунтам. Для исправления нужна ручная чистка БД.

Attachments: скриншот списка сотрудников, выборка из таблицы users.
