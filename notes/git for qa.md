# Git

## 1. Четыре места

| Место | Что это | Где |
|---|---|---|
| Рабочая папка | Файлы, которые видишь и редактируешь | Папка проекта |
| Индекс (staging) | Черновик следующего коммита | `.git` |
| Локальный репозиторий | История коммитов | `.git` |
| Удалённый репозиторий | Копия на GitHub | GitHub |

Команды **копируют**, а не перемещают. Файл в папке никуда не уходит.

```
папка ──add──▶ индекс ──commit──▶ история ──push──▶ GitHub
```

- `git add файл` — копирует **текущую** версию файла в индекс.
- `git commit -m "..."` — сохраняет всё из индекса как снимок в историю.
- `git push` — отправляет новые коммиты на GitHub.

> [!example] Пример
> `add` → дописала строчку → `commit` без второго `add`.
> В коммит уйдёт версия **на момент `add`**: commit берёт только то, что в индексе.

## 2. Коммит = снимок

Коммит — «фотография» всего проекта (как он лежал в индексе) + подпись:
- автор, дата, сообщение;
- ссылка на предыдущий коммит;
- **хеш** (`f782ba9`) — считается из всего перечисленного.

Поменялось хоть что-то (даже дата) → другой хеш.

## 3. Статусы файлов

| Статус | Значит | Цвет в `git status` |
|---|---|---|
| untracked | Git файл ещё ни разу не добавлял | красный |
| modified | Файл уже в коммите, его изменили, `add` не делали | красный |
| staged / new file | Изменение в индексе, ждёт коммита | зелёный |
| clean | Папка = индекс = последний коммит | — |

Цвет относится к **изменениям**, а не к файлу. Один файл может быть и зелёным, и красным одновременно: часть изменений в индексе, часть только в папке.

`nothing to commit, working tree clean` — отличий нет, коммитить нечего.

## 4. Смотреть, что происходит

| Команда             | Что сравнивает                                 |
| ------------------- | ---------------------------------------------- |
| `git status`        | Какие файлы где изменены                       |
| `git diff`          | папка ↔ индекс (что ещё не добавила)           |
| `git diff --staged` | индекс ↔ последний коммит (что уйдёт в коммит) |
| `git log --oneline` | История коротко                                |
| `git reflog`        | Журнал всех перемещений HEAD                   |

Перед каждым `commit` полезно смотреть `git diff --staged`.

**Как читать diff:**
```
--- a/notes.txt      ← версия «до»
+++ b/notes.txt      ← версия «после»
@@ -1 +1,2 @@        ← было: с 1-й строки, 1 строка; стало: с 1-й, 2 строки
 first line          ← без знака: не менялась (контекст)
+second line         ← добавлена
```
Замена строки = пара `-старое` / `+новое`.

Если вывод с `:` или `(END)` внизу — выйти через `q`.

## 5. Отмена

| Команда                       | С чем работает   | Что делает                                      | Опасность                  |
| ----------------------------- | ---------------- | ----------------------------------------------- | -------------------------- |
| `git restore --staged файл`   | индекс           | Убирает изменение из индекса, в папке оставляет | безопасно                  |
| `git restore файл`            | папка            | Затирает изменения в папке версией из индекса   | ⚠️ не добавленное пропадёт |
| `git commit --amend -m "..."` | последний коммит | Заменяет его новым (новый хеш)                  | только до push             |
| `git revert HEAD --no-edit`   | история          | Новый коммит, который отменяет указанный        | безопасно после push       |
| `git reset ...`               | метка ветки      | Двигает ветку на другой коммит                  | только до push             |

- `restore` — про **файлы**, историю не трогает.
- `reset` / `--amend` — **переписывают** историю → после push их push отклонят (`rejected`).
- `revert` — **дописывает** историю → безопасен для запушенного.

### Режимы reset

| Режим | Ветка | Индекс | Папка | Результат в `git status` |
|---|---|---|---|---|
| `--soft` | двигает | не трогает | не трогает | изменения зелёные |
| без флага (`--mixed`) | двигает | из коммита | не трогает | изменения красные |
| `--hard` | двигает | из коммита | из коммита | ⚠️ изменения стёрты |

`HEAD~1` — «коммит на один раньше текущего».

### Спасение через reflog

> [!example] Пример
> ```
> git reset --hard HEAD~1        # ой, не туда
> git reflog
> # f782ba9 HEAD@{0}: reset: moving to HEAD~1
> # afe31a8 HEAD@{1}: commit: Add second line   ← состояние до ошибки
> git reset --hard afe31a8       # вернули
> ```
> `HEAD@{1}` — где HEAD был шагом раньше. reflog локальный и не вечный.

## 6. Ветки и HEAD

- **Ветка** = метка с именем, указывает на один коммит. `main → f782ba9`.
- **HEAD** = метка «где я сейчас», обычно указывает на ветку.
- Цепочка: `HEAD → main → f782ba9`. В логе: `(HEAD -> main)`.
- Коммит двигает **ту ветку, на которую указывает HEAD**. Остальные стоят на месте.

| Команда | Что делает |
|---|---|
| `git switch -c tests` | Создать ветку `tests` на текущем коммите и перейти на неё |
| `git branch` | Список веток, `*` — текущая |
| `git switch main` | Перейти на `main` (папка перезапишется её состоянием) |
| `git merge tests` | Слить `tests` в текущую ветку |

Перед `switch` — чистый `git status`.

**Fast-forward:** если в `main` не было новых коммитов после создания `tests`, merge просто передвигает метку `main` вперёд. Новый коммит не создаётся.
```
до:    A ── B ── C          после:  A ── B ── C
            ↑    ↑                            ↑
          main  tests                    main, tests
```

## 7. .gitignore

Текстовый файл в корне со списком того, что Git не замечает.

```
*.log
.env
allure-results/
__pycache__/
node_modules/
.vscode/
```

- `*` — любое имя. Папка — со слешем в конце.
- Сам `.gitignore` **коммитим**: правило должно быть у всех (коллеги, GitHub Actions).
- Игнорим: секреты, результаты прогонов, служебное, личные настройки.
- Коммитим: тесты, коллекции Postman, README.

> [!warning] Ловушки
> - `.gitignore` действует только на **untracked**. Уже закоммиченный файл продолжит отслеживаться → `git rm --cached файл` + коммит.
> - Секрет, попавший в коммит на GitHub, считать утёкшим: остаётся в истории → менять токен.
> - В Windows PowerShell создавать через `Set-Content .gitignore "*.log"`, не через `>`: может записаться в кодировке, которую Git не прочитает.
